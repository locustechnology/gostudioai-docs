---
title: "Asynchronous requests"
description: "Run long jobs in the background, poll for results, and get an optional webhook."
---

Every generation request creates a **job**. In **sync** mode the request waits for the result, up to 270 seconds. In **async** mode you get a `job_id` and a `poll_url` straight away, and the job runs in the background.

<Note>
Polling is the source of truth. A webhook is an optional extra on top of polling.
</Note>

## When to use it

- **Video:** always async.
- **Recreate, Profile Photo, Recreate Group and Group Photo:** async by default.
- Any job you don't want to hold a connection open for.
- Many jobs at once, sent without waiting for each one.

For fast tools (Age Modifier, Watermark Remover, Weight Shift, Image), sync is simpler: the result comes back in the same response.

## Request fields

| Field | Type | Description |
|---|---|---|
| `mode` | string | `sync` or `async`. Defaults below. Video takes only `async`, or leave it out. |
| `webhook_url` | string | Optional. Public `https` URL that we `POST` to when the job finishes. Works in both modes. |

| Endpoint | Default `mode` |
|---|---|
| Age Modifier, Watermark Remover, Weight Shift, Image create, Image edit | `sync` |
| Group Photo, Recreate, Profile Photo, Recreate Group | `async` |
| All Video endpoints | Always `async` |

Watermark Remover with `model_id: "lite"` is fast enough that it always answers `200` with the result, even with `mode: "async"`.

## Responses

Every generation endpoint answers in one of two shapes.

**`200`: finished** (sync)

```json
{
  "status": 200,
  "data": {
    "job_id": "3f2b8c1e-5d4a-4c1b-9e7a-0a1b2c3d4e5f",
    "status": "completed",
    "output_urls": ["https://…/result.jpg"],
    "credits_deducted": 8,
    "credit_balance": 112
  }
}
```

**`202`: still running** (async, or sync that ran out of time)

```json
{
  "status": 202,
  "data": {
    "job_id": "3f2b8c1e-5d4a-4c1b-9e7a-0a1b2c3d4e5f",
    "status": "processing",
    "credits_deducted": 8,
    "poll_url": "https://www.gostudio.ai/api/v2/jobs/3f2b8c1e-5d4a-4c1b-9e7a-0a1b2c3d4e5f"
  }
}
```

Endpoints that take a `model_id` also return `model_id`.

**Step 1: Submit the job**

<CodeGroup>
```bash curl
curl -X POST https://www.gostudio.ai/api/v2/recreate \
  -H "Authorization: Bearer <api_key>" \
  -H "Content-Type: application/json" \
  -d '{
    "input_image_url": "https://example.com/me.jpg",
    "reference_image_url": "https://example.com/style.jpg",
    "mode": "async",
    "webhook_url": "https://your-app.com/webhooks/gostudio"
  }'
```

```python Python
import requests

API = "https://www.gostudio.ai/api/v2"
HEADERS = {"Authorization": "Bearer <api_key>"}

job = requests.post(f"{API}/recreate", headers=HEADERS, json={
    "input_image_url": "https://example.com/me.jpg",
    "reference_image_url": "https://example.com/style.jpg",
    "mode": "async",
}).json()["data"]
```
</CodeGroup>

You get the `202` response above.

**Step 2: Poll for the result**

Call `poll_url` (or [`GET /jobs/{job_id}`](/api-reference/jobs/get-job-poll)) every 5 seconds.

<CodeGroup>
```bash curl
curl https://www.gostudio.ai/api/v2/jobs/3f2b8c1e-5d4a-4c1b-9e7a-0a1b2c3d4e5f \
  -H "Authorization: Bearer <api_key>"
```

```python Python
import time

while True:
    result = requests.get(job["poll_url"], headers=HEADERS).json()["data"]
    if result["status"] not in ("pending", "processing"):
        break
    time.sleep(5)
```
</CodeGroup>

```json
{
  "status": 200,
  "data": {
    "job_id": "3f2b8c1e-5d4a-4c1b-9e7a-0a1b2c3d4e5f",
    "status": "completed",
    "tool_name": "recreate",
    "created_at": "2026-11-05T10:00:00Z",
    "updated_at": "2026-11-05T10:00:41Z",
    "output_urls": ["https://…/result.jpg"]
  }
}
```

| `status` | Meaning |
|---|---|
| `pending`, `processing` | Still running. Keep polling. |
| `completed` | Done. The files are in `output_urls`. |
| `failed` | Read `error` (`type`, `code`, `message`). Your credits are returned. |
| `abandoned` | The job was stopped and no longer exists. No result will come. |

**Step 3: Optional webhook**

Send a `webhook_url` and we `POST` to it once when the job finishes.

```json
{
  "event": "job.completed",
  "job_id": "3f2b8c1e-5d4a-4c1b-9e7a-0a1b2c3d4e5f",
  "status": "completed",
  "tool_name": "recreate",
  "output_urls": ["https://…/result.jpg"]
}
```

A failed job sends `"event": "job.failed"`, `"status": "failed"` and an `error` object instead of `output_urls`.

- The URL must be public `https` on port 443, with no username or password, and up to 2048 characters.
- We do not follow redirects.
- If your server does not answer with `2xx` (timeout, network error, `408`, `429` or `5xx`), we try again. There are 5 attempts in total over about 90 seconds.

<Warning>
Webhooks are not signed yet. When one arrives, confirm the result with `GET /jobs/{job_id}` before you use it.
</Warning>

## Billing

Credits are taken when the job is accepted and shown in `credits_deducted`. If the job fails, they are returned automatically. Do not send the same request again after a `202`: that creates a second job and charges again.

## Errors

| HTTP | `code` | When |
|---|---|---|
| 400 | `invalid_input` | `mode` is not `sync` or `async`, or a video request sent `mode` other than `async`. |
| 400 | `invalid_webhook_url` | `webhook_url` is not a public `https` URL. |
| 404 | `job_not_found` | No such job for your key. |
| 429 | `rate_limited` | Polled too often. Poll every 5 seconds. |

All other codes are on [Errors](/resources/errors).
